## next.html 当前已实现

### 数据驱动
- 概览、人物、世界、时间线、旅程、能力、携带、项目、情报均从 JSON 渲染；
- 可选字段缺失时容错，不再因为单个字段缺失导致整站崩溃；
- 页面展示字段统一中文，内部 JSON 键名不会直接暴露给用户。

### 多世界作用域
- 当前世界；
- 全部世界；
- 世界01 / 未来世界02 / ……；
- 世界列表从 `data/worlds/index.json` 动态读取。

### 稳定实体与关联
已经纳入稳定 ID 的实体包括：
- 玩家；
- 世界；
- 地点；
- 人物；
- 能力；
- 物品；
- 货币；
- 事件；
- 章节；
- 长期项目；
- 情报。

时间线、章节、项目、情报等通过稳定 ID 建立前向引用，并自动生成 Backlinks / 反向关联。

### 实体详情抽屉
点击人物、能力、事件、章节、项目、情报、世界、地点、物品等实体，会在右侧打开详情抽屉。

当前详情支持：
- 人物：完整已知资料、信息来源、反向关联；
- 能力：来源、效果、限制、跨界状态、最早关联事件、相关正史章节；
- 项目：参与者、已确认、仍未知、缺少条件、风险；
- 情报：结论、证据链、仍未知、关联对象；
- 事件：时间、摘要、关联对象；
- 章节：卷、时间范围、摘要、关联对象、唯一 Markdown 正文来源；
- 世界 / 地点：世界规则、地点、价格和归属关系；
- 物品 / 货币：数量、来源、位置与跨界状态。

详情中的关联对象仍可继续点击，形成连续的档案浏览路径。

## 自动诊断

### 浏览器端
`next.html` 会检查：
- 重复 ID；
- 无法解析的引用；
- 关键结构提醒；
- 实体与引用数量。

### GitHub Actions
- `scripts/validate-data.mjs` 已改为从 `data/worlds/index.json` 动态加载所有世界；
- 检查世界注册表、世界文件、地点 ID、人物 / 能力 / 物品 / 事件 / 章节等引用；
- 检查章节正文来源是否存在；
- 检查项目、情报等数组结构；
- `.github/workflows/validate-data.yml` 还会运行 `node --check assets/next.js`，避免前端 JavaScript 语法错误直接上线。

## 项目命令

只保留两个：

- `存档`：续档、当前状态、结构化数据、网站数据与必要正史章节一起保存；
- `读档`：读取续档入口及权威档案后继续游戏。

## 调研吸收情况

### Obsidian RPG Manager
已经吸收：
- Everything is an Element → 稳定实体 ID；
- 不同页面只是同一事实的不同视图，而不是维护多份事实。

### Chronicler
已经吸收：
- Files are truth → Markdown / JSON 文件是真实数据层；
- Backlinks → 自动反向关联；
- Diagnostics → 浏览器端 + GitHub Actions 双层诊断；
- UI 与数据分离 → `next.html` / CSS / JS / data 分层。

### Chronicle Keeper
已经吸收：
- 游戏对话 → 存档 → 结构化事实 → 网站视图；
- Timeline / Wiki / Journey 多视图；
- 多世界注册与切换骨架。

## 下一步优先级

### P1.1 关系视图
不做游戏化“好感度图”，而是展示：
- 同行；
- 曾同行；
- 合作；
- 帮助 / 受帮助；
- 项目协作；
- 情报来源；
- 物品持有 / 来源。

先做局部实体关系图或关系列表，不急着上复杂全屏图谱。

### P1.2 存档变化记录
每次 `存档` 自动记录本次发生了什么变化，例如：
- 灵石 3 → 5；
- 新人物；
- 新能力；
- 人物失联；
- 新章节；
- 项目状态变化。

目标是以后能回答“这个状态从什么时候变的”。

### P1.3 新世界兼容性检查
进入第二世界后，对能力 / 物品自动生成：
- 待验证；
- 已确认可用；
- 部分可用；
- 规则改变；
- 失效。

这会成为跨世界玩法的重要历史记录。

### P1.4 正式首页切换
待 `next.html` 经实际使用验证没有明显交互问题后，再替换当前 `index.html`。

## 不改变的核心

- 游戏继续在 ChatGPT 中进行；
- 网站不成为 GM 后台或任务系统；
- 公开网站严格保持徐长卿第一视角；
- 徐长卿不知道的后台事实不进入公开结构化数据。

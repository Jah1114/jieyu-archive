# 界域档案 · 长期功能路线图

> 目标：让项目能够支撑数十个世界、数年的长期游玩，同时保持“游戏在对话中进行，GitHub 保存事实，网站负责第一视角档案与历史沉淀”的核心结构。

## 总原则

1. 连续性、安全存档和数据一致性优先于视觉功能。
2. 网站不成为任务面板、GM 后台或游戏本体替代品。
3. 公开档案只显示徐长卿当前认知。
4. 后台设定、剧情真相、NPC秘密与第一视角资料严格分层。
5. 功能增长不能让主导航随世界数量线性膨胀。
6. 同一事实尽量只维护一次，通过稳定 ID 和统一关系层复用。
7. 所有“读档 / 存档”遵循项目来源中的 GitHub 事务规范。

---

## 已完成基础（不再作为未来任务）

以下能力已经形成当前架构基线：

- 数据驱动正式首页；
- `index.html` 已正式使用数据驱动版，`next.html` 作为同构备用入口；
- 全局 / 访问实例分层；
- `data/worlds/index.json` 多世界访问实例注册表；
- 当前世界 / 全部世界 / 指定访问实例作用域；
- 玩家、人物、地点、事件、章节、能力、物品、货币、项目、情报稳定 ID；
- 双向关联与统一关系层；
- 章节 → 长期地点关联；
- 物品 → 获得人物 / 制作人物 / 指导人物 / 获得事件 / 能力关联；
- 长期地点筛选与排序；
- 真正的过滤式搜索；
- 第一视角人物主体；
- 项目与情报证据链；
- 隐藏功能注册与界网未解锁保护；
- 浏览器端诊断；
- GitHub Actions 结构化数据与 JavaScript 校验；
- `archive/SAVE_TRANSACTION.json` 存档事务保护。

这些已经完成的能力不应再被后续 AI 当作“待重做项目”。

## P0：连续性与存档安全增强

这是当前最高优先级。

### P0.1 跨文件语义一致性检查

在现有“格式 / 引用”校验之上继续增加：

- `meta.currentWorldId` 与当前访问实例一致；
- `meta.playerName` 与玩家实体一致；
- `CONTINUITY.md`、`CURRENT_STATE.md` 与 `meta.currentNarrative` 的当前日、时段、地点一致；
- 时间线中明确可解析的事件日不能晚于当前世界日；
- 当前访问实例注册状态唯一；
- 事务为 `clean` 时不得残留活动事务或修复标记。

目标：减少“格式正确但内容互相矛盾”的隐性漂移。

### P0.2 存档变化记录 / Diff

每次正式 `存档` 完成后，生成简短、机器可读或 Markdown 形式的变化记录，例如：

- 时间变化；
- 资源变化；
- 新人物；
- 人物状态变化；
- 新能力 / 新物品；
- 新事件 / 新章节；
- 项目状态变化；
- 功能解锁变化。

用途是审计与连续性追踪，不做游戏结算面板。

### P0.3 事务恢复规则

进一步明确 `in_progress` 的恢复策略：

- 比较目标文件实际写入状态；
- 判断哪些文件已完成、哪些未完成；
- 能安全自动恢复时继续；
- 无法确定时转为 `repair_required`；
- 修复完成前禁止继续游戏。

## P1：人物关系与联系历史

统一关系层已经存在，下一步不是重新设计关系 UI，而是丰富**长期关系事实**：

- 初见访问实例 / 初见事件；
- 最后见面时间；
- 最后通信时间；
- 当前已知状态；
- 同行 / 曾同行 / 合作 / 帮助 / 欠人情；
- 共同经历；
- 是否存在跨界联系方式。

不做数值化好感度，也不公开 NPC 隐藏阵营。

---

## P1：资产位置与仓储

当前私人携带已经结构化。等剧情自然出现储物装备、据点或稳定组织资产后扩展：

- 随身；
- 储物装备；
- 当前据点；
- 同行代持；
- 留在旧访问实例；
- 已损毁；
- 状态未知。

货币按世界 / 访问实例分开，不强行建立汇率。

只有出现稳定组织、共同仓库、基地、飞船或长期基金时，才建立“共同资产”；临时小队零钱不进入长期字段。

---

## P1：能力跨世界兼容历史

进入新访问实例后，旧能力 / 物品默认不是“必然兼容”，而是：

- 待验证；
- 已确认可用；
- 部分可用；
- 规则改变；
- 失效。

记录亲自验证结果，不用后台规则剧透。

这会让“进入新世界后测试旧能力”成为自然玩法。

---

## P1：世界离开冻结快照

离开一个访问实例时形成只读历史快照：

- 停留时长；
- 离开时状态；
- 带走物品；
- 留下资产；
- 最后已知联系人；
- 未完成项目；
- 未解决情报；
- 正史章节范围。

旧访问实例以后原则上只做历史纠错，不被当前世界状态覆盖。

---

## P2：旅程与关系深挖

现有旅程已经能关联长期地点，后续可继续增强：

- 章节关键词；
- 更完整的人物 / 能力 / 物品关联；
- 从人物页反查共同章节；
- 从能力页反查首次学习 / 首次实战章节；
- 从物品页反查获得与使用章节。

仍以 Markdown 正文作为唯一正史过程来源，不复制完整正文到 JSON。

---

## P2：主观日志

与事实档案分开记录徐长卿自己的判断，例如：

- 对人物的信任判断；
- 当前资源优先级；
- 对实验方向的个人想法；
- 对某条情报的怀疑。

主观日志允许之后改变，也不等于客观事实。

---

## P2：搜索与关系检索增强

现有搜索已经是真过滤。后续可增强为：

- 按实体类型筛选；
- 按访问实例筛选；
- 按关系角色搜索（赠予 / 传授 / 制作 / 指导等）；
- 从一个实体追踪完整关系链。

不引入复杂的游戏化知识图谱 UI，优先保持阅读效率。

---

## P3：界网模块（仅剧情解锁后）

只有徐长卿在正史中实际接触并确认界网，`data/features.json` 对应功能完成第一视角解锁后才上线。

未来可包含：

- 连接状态；
- 好友；
- 私信；
- 社区；
- 知识库；
- 开源项目；
- 节点；
- 收藏 / 来源情报。

重要原则：

- 界网不是界域官方系统；
- 界网内容也是情报，不是真理；
- 无节点时允许离线；
- 不提供实物跨界物流、自动救援、复活或全知定位。

---

## P3：备份与可迁移性

长期项目不能只依赖在线页面。

未来考虑：

- 可下载的 Markdown / JSON 全量快照；
- 每个重要世界结束时 Git tag / Release；
- 重要阶段生成归档包；
- 简单的恢复说明。

目标是即使未来不再使用 GitHub Pages，也能无损迁移。

---

## 推荐实施顺序

近期：

1. 跨文件语义一致性检查；
2. 存档 Diff / 变化记录；
3. 事务恢复规则；
4. 人物长期关系事实。

第二阶段：

5. 资产位置 / 仓储；
6. 能力跨世界兼容历史；
7. 世界离开冻结快照；
8. 旅程关系深挖。

自然需要时：

9. 主观日志；
10. 搜索增强；
11. 备份 / Release。

剧情达到条件后：

12. 界网公开模块。

最重要的判断：

> **接下来不重做已经稳定的首页、关系层或数据拆分；优先把“长期不会写乱”继续做扎实。**

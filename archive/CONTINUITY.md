# 对话续档入口（Continuity Handoff）

> 用途：GitHub 侧跨对话续档入口。动态剧情以本文件及相关权威档案为准。稳定安全规则以项目来源中的《界域长期项目_统一运行规范_GitHub活协议版.md》为准；当前仓库架构与实际读写路径以 `archive/OPERATION_PROTOCOL.md` 为准。

## 最重要的操作规则

**每一次 `读档` 和每一次 `存档`，都必须在本次操作中重新：**

1. 查看项目来源中的统一运行规范；
2. 读取 `archive/OPERATION_PROTOCOL.md`；
3. 读取 `archive/PERSISTENCE_MAP.json`；
4. 再按最新协议读取 / 操作 GitHub。

不得因为当前聊天早些时候已经读过规则，就假定那一份仍是最新版。

这条规则用于保证：即使主游戏聊天不知道维护聊天后来修改了仓库架构，它下一次存档时也会先重新获得最新规则。

## 两个核心命令

### `读档`

读档是只读操作。

本次操作必须先重新查看项目来源，然后读取：

1. `archive/SAVE_TRANSACTION.json`
2. `archive/OPERATION_PROTOCOL.md`
3. `archive/PERSISTENCE_MAP.json`
4. 本文件 `archive/CONTINUITY.md`
5. `archive/CURRENT_STATE.md`
6. `data/meta.json`

只有同时满足：

- `state = clean`；
- `activeTransaction = null`；
- `repair.required = false`；
- 核心连续性文件可以互相解释；

才允许继续读取人物、能力、携带、世界、时间线、章节、项目、情报等权威文件并恢复游戏。

如果事务状态异常、协议冲突、关键文件互相冲突或 GitHub 无法可靠读取：禁止凭记忆继续游戏。

### `存档`

存档是完整连续性保存，不是只记录最后一句剧情。

**每一次存档都重新同步规则。** 本次操作必须：

1. 重新查看项目来源中的统一运行规范；
2. 重新读取 `archive/OPERATION_PROTOCOL.md`；
3. 重新读取 `archive/PERSISTENCE_MAP.json`；
4. 重新读取 `SAVE_TRANSACTION.json`、本文件、`CURRENT_STATE.md`、`meta.json` 和本轮所有目标文件；
5. 获取目标文件最新 SHA；
6. 对比本轮新事实与 GitHub 当前事实；
7. 根据真实变化声明 `changeDomains`，并按持久化映射覆盖最低目标文件；
8. 正式写入前把事务设为 `in_progress` 并列出 `targetFiles`；
9. 先写真正发生变化的结构化事实；
10. 自然章节节点才更新章节 / 正史；
11. 更新状态摘要与元数据；
12. 本文件接近最后更新；
13. 重新读取关键文件并等待 GitHub Actions；
14. 校验通过后才把事务恢复为 `clean` 并宣布“存档完成”。

任何中途失败、协议冲突、版本冲突、部分写入或自动校验失败，都不能声称存档完成。

**“最新叙事前沿”只是续写坐标，不等于完整存档。**

## 读档权威文件

按需要读取：

- `archive/SAVE_TRANSACTION.json` —— 存档事务状态；
- `archive/OPERATION_PROTOCOL.md` —— 当前仓库活操作协议；
- `archive/PERSISTENCE_MAP.json` —— 当前持久化结构映射与 `changeDomains` 契约；
- `archive/CURRENT_STATE.md` —— 当前状态权威摘要；
- `archive/PEOPLE.md` —— 第一视角人物档案；
- `data/meta.json` —— 当前世界与叙事前沿机器坐标；
- `data/global/player.json` —— 徐长卿结构化状态；
- `data/global/people.json` —— 人物状态；
- `data/global/abilities.json` —— 能力与跨界状态；
- `data/global/inventory.json` —— 私人携带、货币与市场观察；
- `data/worlds/index.json` + 当前访问实例世界文件 —— 世界和长期地点；
- `data/timeline.json` —— 已发生重要事件及关联；
- `data/chapters.json` + `story/` —— 章节索引与正史正文；
- `data/projects.json` / `data/intel.json` —— 长期项目与情报证据链；
- `data/features.json` —— 功能注册与第一视角解锁状态；
- `lore/SETTING.md` —— 后台世界规则，严禁直接当成徐长卿已知；
- `docs/UI_ARCHITECTURE.md` —— 多世界档案界面规范。

事实冲突优先级：

1. 用户当前明确纠正；
2. 已发生正史正文 / 章节；
3. 本文件最新叙事前沿；
4. `archive/CURRENT_STATE.md`；
5. 最新结构化数据；
6. 第一视角人物 / 情报档案；
7. 后台设定；
8. 模型推测。

无法确认时保持未知。

## 叙事与玩法规则

- 除执行 `读档` 后开头允许有必要的游戏外状态说明外，一旦进入正式剧情，普通回复应持续沉在故事中。
- 不用“你准备怎么做？”“请选择行动”“接下来可以……”等主持人式界面收尾；用户的自然语言输入本身就是徐长卿的行动、语言、思考或意图，世界直接作出反应。
- 不给固定 A/B/C 菜单。
- 世界独立运行，NPC 有自己的动机与生活。
- 原作是初始条件，不是剧情铁轨。
- 信息严格不全知；玩家没获知的后台事实不能泄露。
- 战斗、交易、资源、时间、伤势有现实成本；死亡原则真死。
- 徐长卿不强行当领袖；叶青可自然承担更多多人交涉。
- 安稳修炼、制符、低风险挣钱都是有效路线。
- 具体小说文体以项目来源中的《界域_叙事文体与小说写作规范_v2.md》为准；主游戏应减少重复流程的逐笔复写，已经验证过的同类生产、交易和日常过程可以压缩，只详细呈现出现新信息、新变化或重要人物互动的节点。

# 界域档案：长期多世界界面规范

> 目标：即使未来经历 10、20、50 次跨界，甚至多次重返同一个作品世界，主界面仍然稳定、清楚，不因世界、地点和事件数量增加而无限膨胀。

## 一、核心原则

### 1. 主导航永远稳定
左侧一级导航不按世界增加栏目。长期保持类似：

- 概览
- 人物
- 世界
- 时间线
- 旅程
- 能力
- 携带
- 项目
- 情报
- 界网（只有徐长卿真正接触后才解锁）

禁止把世界01、世界02、世界03逐个塞进侧栏。

### 2. “世界记录”本质上是访问实例

一个作品/IP世界并不保证只进入一次。

因此数据层分为：

- **作品世界（setting）**：例如《凡人修仙传》；
- **访问实例（visit/world record）**：徐长卿某一次实际进入该作品世界的经历；
- **时间线标识（timeline）**：用于记录本次访问与其他访问是否属于同一条时间线。

例如未来可能出现：

- 记录01 · 《凡人修仙传》· 第1次访问 · 时间线A；
- 记录07 · 《凡人修仙传》· 第2次访问 · 与记录01同一时间线；
- 记录15 · 《凡人修仙传》· 第3次访问 · 疑似不同时间线；

时间线关系只有在徐长卿获得足够证据后才确认；无法判断时写“尚未确认”，不能后台强行合并。

### 3. 页面使用统一作用域切换器

顶部世界切换器提供：

- 当前世界；
- 全部世界；
- 记录01 · 凡人修仙传 · 第1次访问；
- 记录02 · ……

切换器只决定当前页面展示哪个访问实例的信息，不改变主导航结构。

### 4. 信息分为跨世界层与访问实例层

跨世界永久层：
- 徐长卿基础档案；
- 无量灵海；
- 已保留能力；
- 跨界物品；
- 行者好友/长期联系人；
- 总旅程；
- 界网。

访问实例局部层：
- 当前地点；
- 本地身份；
- 势力；
- 当地货币；
- 本地人物；
- 事件；
- 情报；
- 章节。

## 二、地点档案：长期记忆节点，而不是事件坐标库

### 收录标准

“已知地点”只收录至少满足一项的地点：

1. 可能反复进入或长期停留；
2. 是重要城市、宗门、聚居地、据点、交通/交易枢纽；
3. 承载重大事件，未来回顾价值明显；
4. 与重要联系人、资源渠道、长期项目或资产有关；
5. 未来有合理概率再次访问。

不应因为“某件事发生在那里”就自动建立地点实体。

例如：一次性客栈、路边、临时溪边、普通委托目的地、摊位等，可以留在事件摘要/正文里，但默认不进入长期地点列表。

### 当前排序

地点默认使用 **重要度排序**：当前枢纽、长期落脚、重大事件地优先。

用户可切换：

- 重要度；
- 首次到达；
- 名称（中文本地化排序）。

不采用“永远按首次到达时间”作为唯一顺序，否则在长期世界中真正重要的地点会被大量旧地点淹没。

## 三、搜索规则

搜索是**过滤器**，不是高亮器。

输入关键词后：

- 当前页面只保留匹配卡片；
- 不匹配内容直接隐藏并释放布局空间；
- 显示当前匹配数量；
- 清空搜索立即恢复全部内容；
- 世界作用域切换后继续应用当前搜索词。

禁止仅把非匹配内容变暗，因为长页面仍会迫使用户滚动寻找结果。

## 四、第二世界及后续首页

首页固定分三层：

### A. 当前状态
只显示当前访问实例：当前世界、当地第几天、地点、身份、境界/力量状态、身体/法力、离界状态、当前同行。

### B. 跨界资产
只显示真正跨世界保留的重要内容：核心天赋、已确认跨界能力、储物装备、关键物品、可联系行者。

### C. 最近旅程
显示最近3–5个重要事件，可跨世界。

旧访问实例不在首页占大面积内容，只保留可进入历史档案的入口。

## 五、“世界”页面

世界页是所有**访问实例**的总目录，而不是作品IP去重后的列表。

每个记录卡显示：

- 全局记录编号；
- 作品世界名称；
- 第几次访问该作品世界；
- 时间线关系/状态；
- 当前/已离开；
- 停留时长；
- 本地身份；
- 关键收获；
- 长期地点数量；
- 正史章节数量。

默认最新访问实例在前。

点击记录后查看概况、长期地点、人物、势力、情报、时间线、旅程、获得物。

## 六、“人物”页面

人物页默认按当前访问实例过滤，但徐长卿本人固定置顶。

长期字段包括：
- 初见访问实例；
- 最后见面/通信实例；
- 当前已知状态；
- 是否可跨界联系；
- 界网身份（解锁后）。

旧世界人物不会删除，只是在当前世界视图中降低干扰。

## 七、“时间线”页面

顶部作用域：当前世界 / 全部世界 / 指定访问实例。

不同世界不强行换算统一历法，例如：

> 记录01 · 第85天 · 七玄门大战

> 记录02 · 第3天 · ……

事件只有在其发生地点属于“长期地点”时才建立地点关联。微型地点仍可存在于事件文字中。

跨界事件（离界、进入新世界、跨界通信、能力跨界验证）单独标记为界间事件。

## 八、“旅程”页面

旅程采用“访问实例/卷 → 章”结构。若未来重返同一作品世界，不覆盖旧卷，而是新增访问卷/记录。

正文仍遵循：正史才进入；废案不进入；整理稿明确标注；不冒充逐字聊天原文。

## 九、“能力”页面

能力是跨世界全局页面，每项记录：来源访问实例、获得方式、当前掌握程度、当前世界能否使用、跨界兼容状态、能源类型、已知限制。

不做游戏化技能树等级。

## 十、“携带”页面

长期记录物品位置：随身、储物装备、当前世界据点、某同行持有、留在旧世界、状态未知等。

只保存有长期价值的资源与物品；极短期的共同零钱不进入长期资产层。

## 十一、“情报”页面

情报强制带作用域和来源：亲眼确认、亲自测试、本人自述、同行/NPC告知、原作记忆、未来的界网帖子/Wiki、推测、未确认等。

## 十二、“界网”解锁后的处理

界网是跨世界全局基础设施，解锁后成为一级导航，包括连接状态、好友、私信、社区、知识库、开源项目、节点、收藏。

当前剧情尚未接触时，公开网站不展示“锁住的界网按钮”，避免第一视角泄密；后台仅在功能注册表中预留。

## 十三、桌面与移动布局

桌面：左侧导航约220–240px，内容在剩余区域居中，最大宽约1400–1520px，作用域切换器与搜索共存。

移动：主导航横向滚动或底部化，世界切换器靠近顶部，旧世界默认折叠，卡片单列/双列。

## 十四、数据结构

```text
/data
  /global
    player.json
    people.json
    abilities.json
    inventory.json
  /worlds
    index.json
    world-01.json     # 一次访问实例
    world-02.json
  timeline.json
  chapters.json
  projects.json
  intel.json
  features.json
/story
/archive
/lore
```

`worlds/index.json` 同时登记 `settingId / visitIndex / timelineId`，使同一作品世界能够被多次进入且不会互相覆盖。

## 十五、进入新访问实例时

1. 冻结上一访问实例最终状态；
2. 新建新的 `world-XX.json`；
3. 若作品曾去过，复用 `settingId`，增加 `visitIndex`；
4. 根据证据决定复用旧 `timelineId`、创建新时间线，或先标记关系未知；
5. 首页切换到新实例；
6. 验证能力和物品跨界兼容性；
7. 加入离界/进入事件；
8. 旅程新增对应卷；
9. 不覆盖旧实例的地点、身份、人物关系与当地经济记录。

项目命令仍只有：**存档、读档**。
